# Superbot 总览面板 · 设计规范 v1

- 日期：2026-11-06
- 范围：`packages/dsh-superbot/lib/client.js` 的侧栏「Superbot」面板（`sidebar.panellist` + `main`）
- 目标：把「多项目 / 多线程 / 待人工验收」的工作面板从「字段堆叠」改成**可扫读的控制台**：3 秒回答「有多少活、卡在哪、要我做什么」
- 参考：Linear Inbox/Triage、GitHub Projects Table、Sentry Issue Priority、Notion Database views、Vercel Query（见 §1）
- 验收：真机浏览器（隔离 DSH web）+ 深浅色 + 1440/1280/1024/800 四档宽度，截图见 `（历史验收证据已归档，不在本仓库）`

---

## 0. 问题诊断（改造前）

旧面板把「所有能拿到的字段」平铺：

| 问题 | 表现 | 后果 |
|---|---|---|
| 注意力与数据同权 | 顶部 5 个 KPI 大卡 + 每项目 8 个等宽计数 chip | 用户要先扫 40 个数字才知道要做什么 |
| 卡套卡套表 | 项目卡 → 内嵌两张表（线程/待验收） | 层级 3 层，视觉噪音大 |
| 原始 ID 直出 | runId、child session UUID 原样展示 | 不可读，且泄露实现细节 |
| 状态语义弱 | 状态是英文码；颜色小字对比度不足 | 灰度/低视力下不可辨 |
| 无优先级 | 项目按 inventory 顺序；待办散落 | 找不到「现在该处理什么」 |
| 动作分散 | 每行都可能有按钮 | 误操作风险 |

## 1. 参考范式（取什么 / 不取什么）

| 参考 | 关键模式 | 我们采用 | 不采用 |
|---|---|---|---|
| [Linear Inbox + Triage](https://linear.app/docs/inbox) · [Triage](https://linear.app/docs/triage) | 单一收件队列，把「需要你注意」与其余更新分开；Triage 内就地处理（接受/拒绝/推迟） | 全页唯一「待你处理」队列 + 行内验收动作 | 不做多套 inbox 规则 |
| [GitHub Projects Table](https://docs.github.com/en/issues/planning-and-tracking-with-projects/customizing-views-in-your-project/customizing-the-table-layout) | 高密度表格、group/sort/filter、组头汇总、字段显隐 | 项目组合用表格；首屏 5 列，其余进展开 | 不做保存视图/拖拽排序（P2） |
| [Sentry Issue Priority](https://docs.sentry.io/product/issues/issue-priority/) | 按 actionability 排序，行内 owner + last seen + 状态 | 项目状态由工作态派生（待你处理 > 进行中 > 空闲）；行内相对时间 | 不引入三级 priority 分类学 |
| [Notion database views](https://www.notion.com/help/views-filters-and-sorts) | 属性显隐、side-peek 渐进展开、冻结首列 | 点行展开项目详情，不跳页；每层只显示该层属性 | 不做多视图切换 |
| [Vercel Query](https://vercel.com/docs/query) | 摘要 → 过滤 → 下钻 trace/logs 四层同构 | 全局注意力 → 项目组合 → 项目详情 → 原始审计 | 不做查询语言 |

**共同结论**：优秀的「工作面板」不是把所有数据摆出来，而是**按行动优先级分层 + 用表格承载密度 + 把原始数据降级到折叠层**。

## 2. 信息架构（4 层）

```
L1 全局条（sticky）
    Superbot · 工程经理控制台 | 项目 N · 未完成任务 N · 待你处理 N · 活跃线程 N | 更新于 x | 刷新

L2 首次接入盘点（未确认时整卡；确认后压成一行状态）
    摘要 + 项目建议表（状态/线程/未完成任务/依据）+「确认盘点结果」

L3 待你处理（唯一需要人动手的队列；也是全页唯一「通过验收」按钮位置）
    任务名 + 原因 badge（中文）+ 项目 + 证据 n/n + 原因说明 + 备注 + 动作

L4 项目组合（一行一项目，按最近活动排序）
    项目 | 状态 | 任务进度 | 线程（活跃/总 + 历史会话） | 最近活动 | 展开
    └─ 展开：未完成任务表 → 账本线程表 → 历史会话表 → 原始标识（折叠）

L5 页脚：账本与隔离边界（永远折叠）
```

**字段归属原则**：

| 层级 | 字段 | 展示形式 |
|---|---|---|
| 首屏必现 | 项目名/path、派生状态、任务进度、活跃线程、相对活动时间、待处理数 | 表格单元格 |
| 展开可见 | 未完成任务（状态/优先级/执行者/命令数/更新时间）、账本线程（角色/状态/任务/开始/打开会话）、历史会话（标题/推断状态/最后活动） | 行内展开 |
| 永远折叠 | projectId、runId、childId、reviewId、账本目录、事件数、隔离说明 | `<details>` |

## 3. 布局与响应式

- **按面板容器宽度适配**（不是浏览器宽度）：`main` 面板在 1280 窗口下内容宽约 932px。
  实现：`.sb-page-inner { container-type: inline-size }` + `@container`。
- 断点：`≥860px` 全列；`680–859px` 隐藏「线程 / 最近活动」；`<680px` 再隐藏「状态」（状态仍可从展开里看）。
- 内容宽度上限 1120px，页边距 28px；行高：项目行 44px、任务/线程行 42px、表头 30px。
- 间距只用 4/8/12/16/24/32；字号 20（页标题）/15（数字）/13（正文）/12.5（表格）/12（次要）/11（caption），数字 `font-variant-numeric: tabular-nums`。
- 全页层级 ≤2 层：`details` 折叠不再套卡片；表格只用 1px 底边线，无竖线。

**列宽（1440 / Wide）**：项目 33% · 状态 13% · 任务进度 18% · 线程 13% · 最近活动 20% · 展开 3%。

## 4. 字段映射（原始字段 → 人读）

| 原始 | 展示 | 规则 |
|---|---|---|
| 任务状态 `todo/in_progress/in_review/blocked/done/canceled` | 待办/进行中/待验收/阻塞/完成/取消 | 中文；状态色只做 6px 圆点，文字用 primary/secondary |
| 项目派生状态 | `待你验收 N` / `进行中` / `空闲` | 优先级：pendingHuman>0 → 待你验收；activeRuns>0 → 进行中；否则空闲 |
| `pendingHuman.reason` `awaiting-verifier` | 等待验证 | 中文 badge；不再显示英文码 |
| `policy-human-required` | 策略要求人工验收 | 同上 |
| `evidence-incomplete` / `verifier-failed` | 证据不完整 / 验证未通过 | 同上 |
| `detail` 里的策略码 `risk-not-low` / `irreversible` / `tag:aesthetic` | 高风险 / 不可逆变更 / 涉及审美 | 机器码一律 humanize，不直出 |
| `owner`（runId，如 `r-24`） | `worker · 2d193253`（join 账本线程） | 找不到线程 → 「执行者未知」；runId 只留在 title |
| 线程 label `worker:t-4` / `verifier:t-4` | `执行 · t-4` / `验收 · t-4` | 前缀翻译，避免英文标签 |
| `childId` / `sessionId` UUID | 8 位短号（session 去掉前缀） | 完整值退回 title / 原始标识折叠 |
| 时间戳 | 刚刚 / N 分钟前 / N 小时前 / N 天前 / 日期 | `title` 给绝对时间；比较用 `updatedAt / startedAt / lastActivityAt` |
| 计数 | 只渲染 >0；进度 `done/total`；线程 `活跃 / 总数` | 0/0 不显示复合数字；空进度显示「—」 |
| `phase` | 不作为主状态 | 仅历史/调试可用 |

**动作分级（防误验收）**：

| 场景 | 主按钮 | 验收路径 |
|---|---|---|
| 证据完整、策略要求人工验收（`policy-human-required` / `awaiting-human`） | 通过验收 | 一键 |
| 证据不完整 / 验证未通过 / 等待验证 | 打开执行会话（有子会话时） | 「仍要通过验收…」二次确认，并提示「会覆盖证据不足并记入账本」 |

## 5. 视觉规则（含 DSH token 实测）

- **只用主题 token，不写死颜色**：`--dsw-alias-bg-base / bg-layer-1 / border-l2/l3/l4 / label-primary/secondary/tertiary / state-* / button-primary-fill / interactive-bg-hover`。
- **实测坑（已修）**：
  - `--dsw-alias-brand-primary` 是黑白对比色，不是蓝色；蓝色是 `--dsw-alias-state-business-primary`。→ 进行中/活跃/主进度条用 business。
  - `--dsw-alias-label-danger` 不存在；错误文字用 `--dsw-alias-label-error`。
  - 状态色不用于小字：amber/green 小字对比度不足 → 颜色只做圆点/进度填充，文字用中性色。
  - 主按钮背景用 `--dsw-alias-button-primary-fill` + `--dsw-alias-label-primary-inverted`（浅色约 18.9:1）。
- Pill：统一中性边框 + 彩色圆点 + 中性文字；不再用彩色边框/文字表达状态。
- 交互：hover/焦点/容器查询用一次性注入的 `<style id="superbot-panel-css">`（inline style 表达不了，且避免每行 `onMouseEnter` setState 重渲染）。
- 无障碍：项目行本身不加 `role=button`；展开用独立 `<button aria-expanded>`（避免交互元素嵌套）；按钮 `aria-label`；`focus-visible` 2px 焦点环。
- 动效仅 120ms background/border 过渡。

## 7. 验收清单（已逐项人工核对截图）

1. 3 秒三问：有多少项目/多少活、卡在哪、我要做什么 → 首屏可见。
2. 首屏无 KPI 墙；全页每个计数最多出现 2 次。
3. 项目行 ≤6 个视觉元素、≤2 个 badge。
4. 层级 ≤2；无卡套卡套表。
5. 首屏不出现原始 UUID/runId；只在折叠/短号/title 中出现。
6. 状态、原因、优先级全中文；无英文机器码。
7. 高危/证据不足的验收不直通，需二次确认。
8. 「通过验收」动作只出现在待你处理队列。
9. 宽窄屏不溢出；1024 隐藏次要列；800 仍可用。
10. 深/浅色对比可读；状态在灰度下仍可辨（圆点 + 文本）。
11. 键盘可达：展开按钮可 Tab 聚焦，Enter 触发展开。
12. 空/加载/错误态齐全；轮询不闪跳。

## 8. 视图与筛选（P2 已实现）

项目表格上方的视图工具条：

| 控件 | 行为 |
|---|---|
| 筛选 chips：全部 / 待你验收 / 进行中 / 空闲 | 服务端 `GET /superbot/overview?filter=`（`attention`/`active`/`idle`），只过滤项目表；顶部汇总与「待你处理」始终是全量 |
| 排序 select：最近活动 / 待处理优先 / 名称 | `?sort=activity|attention|name`；`attention` 先按 pendingHuman 数再按活跃线程 |
| 搜索框 | `?q=` 匹配项目名或路径，大小写不敏感 |
| 清除 | 一键回到「全部 + 无搜索」，保留排序 |
| 视图记忆 | `localStorage['superbot:panel:view:v1']` 自动保存筛选/排序/搜索，刷新/重开面板恢复（已实测 reload 后恢复） |

筛选结果为空时显示可操作的空态（"没有匹配的项目：换个筛选条件，或点「清除」"）。
服务端同时补齐了看板需要的派生字段：`pendingHuman.priority/risk/updatedAt/workerChildId`、`threads[].taskTitle`、
`view.{filter,sort,q,matchedProjects,totalProjects}`；`pendingHuman` 按 priority + 更新时间排序。

**键盘导航**：项目区内按 `J/K` 或 `↑/↓` 在项目行间移动焦点，`Enter` 展开/收起（按钮带 `aria-expanded`；已实测）。

## 9. 调度对话入口与结构化发单（P2 实现）

### 9.1 对话入口（用户问题：入口在哪）

旧版面板只有总览，没有进入/新建 Manager 会话的入口。现在：

| 入口 | 行为 |
|---|---|
| 头部「调度对话」主按钮 | 有 Manager 会话 → 打开最近一条；没有 → 用当前项目新建 `superbot-manager` preset 的空白会话 |
| 头部「▾」 | 下拉：最近 5 条 Manager 会话 + 按项目新建 |
| 项目展开 / 发单结果「打开调度会话」 | 在指定 workspace 新建或复用 Manager 空白会话；发单场景会把生成的 Manager 提示词填入输入框（已有草稿则保留，不覆盖） |
| 空会话提示 | 无 Manager 会话时显示一行「对话入口：点调度对话，或左侧 New Session 选择 Superbot Manager preset」 |

实现：客户端 `main` slot 注入 `openManagerSession(workspaceId, prompt?)` → 宿主 `uiWorkspace.startSession(workspaceId, { agentPreset: 'superbot-manager', prompt })`（`startSession` 会建/复用空白会话并导航主视图；`prompt` 走 draft 初始化）。没有 `startSession` 的宿主降级到 `connectWorkspace + openSession`。

### 9.2 结构化发单（意图 → 高能量 brief）

面板头部「结构化发单」展开卡片：

1. **输入**：意图（必填）、项目（必填）、背景、任务标题、验收标准（一行一条）、机器验收命令（默认 `node --test`，模板白名单）、约束、非目标、风险、可逆/外部副作用。
2. **本地草稿**：`localStorage['superbot:panel:compose:v1']` 自动保存，刷新不丢。
3. **生成**：`POST /superbot/compose`（纯函数，**不写账本**）返回：
   - `draft`：标准化 requirement + task（可直接进 plan 的形状）；
   - `quality`：`score/grade/missing/warnings`（缺意图/验收/命令/约束/非目标/风险→扣分；模糊词/低风险却声明外部副作用/高风险却声明可逆→提醒）；
   - `ladder`：L0 意图 → L1 可验收需求 → L2 边界/约束 → L3 任务 brief → L4 证据（ok/partial/missing/later）；
   - `brief`：复用 `buildTaskBrief` 的 10 段 worker 合约预览；
   - `managerPrompt`：给 Manager 的高要求前置提示词（最多问 3 个阻塞问题、必须原样使用 acceptanceCommands、不许自己改代码）。
4. **出口**：复制 brief / 复制 Manager 提示词 / 打开调度会话（提示词自动填入输入框）。
5. **不做**：不创建 requirement/plan、不派工、不写账本；用户发送到 Manager 后仍走完整的需求→计划→派工→证据→验收链路。

质量规则（`lib/compose.js`）：结构完整优先（40/25/20/8 分档），模糊词与矛盾降分；`grade A≥85 / B≥70 / C≥50 / D<50`。命令必须通过 `command-policy.js` 白名单，避免「生成器把非法命令带进账本」。

### 9.3 前后端契约

```
POST /superbot/compose
body: { intent, projectId, title?, background?, acceptance?|string[], acceptanceCommands?|string[],
        constraints?, nonGoals?, risk?: 'low'|'normal'|'high', reversible?: boolean,
        externalSideEffects?: boolean, priority?: 'normal'|'high' }
200: { ok: true, draft, quality, ladder, brief, managerPrompt }
400: { ok: false, errors: [{field,message}], quality, ladder }
405: { error: 'method not allowed' }
```

- 信任栅栏与其它路由一致（`connection.requestRejection`），浏览器 cookie 即人类身份。
- 输入长度/数量有界：intent ≤4000、列表 ≤20 条、命令 ≤10 条；非法命令整单返回 400。
- 该路由不写账本，不需要单实例锁参与；同一进程内可并发调用。
