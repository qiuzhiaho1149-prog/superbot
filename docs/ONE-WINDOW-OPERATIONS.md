# 单窗口管理：一个会话管理所有项目/线程

核心目标：**老板只开一个 Superbot 会话窗口**，就能看到所有项目的进度、异常和需要拍板的事；只有必须逐行看证据/做复杂核对时才打开面板。

## 1. 会话里能做什么

| 场景 | 会话内行为 | 何时需要面板 |
|---|---|---|
| 看全局 | 每次老板发消息/worker 收尾后，Manager 调 `superbot_fleet_status`，用 1 行总览（进行中/待你决定/阻塞）+ 变化项汇报 | 想看完整地图/甘特/历史全量时 |
| 审进度 | 按项目给：完成/进行中/待验收/返工/卡住；只列变化，不刷全量任务 | 需要逐条看任务/证据时 |
| 人工审批 | 需要你决定时，会话里列：项目/任务/为什么要你/证据通过数/建议动作；你说“通过”→ `superbot_task_accept`；说“退回”→ `superbot_task_reject`；两者都会弹宿主授权确认，你点允许才算数 | 需要看证据原文、因果时间线、批量核对时打开面板 |
| 下一步/授权 | Manager 直接问“是否继续/是否派工/选 A 还是 B”，你口语回答即可；高风险动作走宿主 approval | 需要看完整上下文时 |
| 异常 | 失败/卡住/返工/验收阻断，先说明原因和证据数，再给建议动作；不贴长日志 | 需要复现/看原始输出时 |

## 2. 为什么不会把会话刷爆

- `fleet_status` 只返回计数、变化项、待你决定项、活跃线程；不是全部任务列表。
- Manager 被要求：先一行总览，再只列**需要你动作**的项；不复述每个 worker 的报告。
- 证据原文、任务详情、因果时间线留在面板；会话只给结论和决策点。
- 项目恢复靠 `SUPERBOT-HANDOFF.md` + `superbot_project_overview`，不重放历史聊天。

## 3. 授权边界（谁点允许）

- `superbot_task_accept` / `superbot_task_reject` 都只能**发起**宿主 approval，Agent 不能自己点允许；老板在弹窗点允许才写入账本。
- 低风险且证据齐全的任务可由 policy 自动完成，不打扰老板。
- 高风险/审美/范围/外部副作用必须人工；面板和会话两条路径等价。
- 面板直连默认关闭（`httpHumanActions=false`），避免任何 Agent 绕过 approval。

## 4. 会话式汇报格式（Manager 约定）

```
[总览] 进行中 2 · 待你决定 1 · 阻塞 0
[需你决定] proj-a / t-12 调整登录页主色：证据 3/3，建议通过
[变化] proj-b 的导出 CSV 已完成；proj-c 的 worker 卡住 35 分钟，建议取消重派
[下一步] 要我继续派 proj-b 的下一项吗？
```

老板回复：
- “通过” → Manager 调 `superbot_task_accept`（宿主弹窗确认）
- “退回/改” → `superbot_task_reject`（宿主弹窗确认）
- “先别动/给我看证据” → 打开面板对应任务；不派工

## 5. 边界

- 会话不替代验收证据；Manager 的总结只是索引，最终 done 由 ledger/policy/human 决定。
- 面板不是第二套系统：它读同一账本投影，只提供详细视图和人工操作入口。
- 关闭插件后，项目 handoff/地图保留，普通会话可继续；重新开启后账本恢复。
